Application overview

From machine log to SIMSE record, automatically.

SIMSE Connector sits quietly between your test equipment and your SIMSE server, handling the parsing and transmission so operators and engineers don't have to.

01 · SOURCE
Test machine
ICT / FCT · writes log
The machine writes a result file to a shared or local folder as testing completes — sometimes line by line, sometimes all at once.
02 · WATCH
Folder monitor
UTF-8 / UTF-16 aware
SIMSE Connector watches the target folder continuously, tolerating partial writes until a complete record appears.
03 · EXTRACT
Field detection
Serial · Result · Machine ID
Once a result is complete, it's parsed for serial number, PASS/FAIL outcome, machine name, and machine code — then checked against duplicates.
04 · SEND

The clean record is sent to the SIMSE server over the API — no operator involvement, no re-keying.

Capabilities

Built for the realities of a production floor.

Every feature exists because a real test line needed it — flaky file writes, mixed encodings, and machines that don't wait for anyone.

Real-time monitoring

Watches machine output folders continuously, reacting the moment a new file or line appears — not on a polling delay.

ICT & FCT integration

Ships with format handling for both In-Circuit Test and Functional Circuit Test machine output.

Automatic PASS / FAIL detection

Parses each completed result and classifies it correctly, regardless of how the machine formats its output.

UTF-8 & UTF-16 support

Reads log files correctly across the encodings different machine vendors default to, without configuration.

Partial write handling

Machines that write results gradually don't produce broken data — Connector waits until a record is genuinely complete.

Duplicate prevention

Already-processed results are tracked and skipped, so a re-read file or a machine retry never double-submits.

Automatic API transmission

Every extracted result is pushed to the SIMSE server as soon as it's validated — no batch jobs, no manual export.

Lightweight footprint

Runs quietly in the background as a Windows service, using minimal memory and CPU on shop-floor PCs.

Built for production environments

Designed around how factory floors actually run — unattended, always on, and tolerant of machine quirks.
